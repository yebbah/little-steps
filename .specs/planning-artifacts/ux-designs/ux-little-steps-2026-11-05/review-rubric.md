# Spine Pair Review — LittleSteps

## Overall verdict
The pair is a solid, buildable contract for the P1 core loop (Today → Prep → Practice → Review). Every color token has a hex value and a dark twin, the contrast claims check out (lowest text pairing is 5.29:1, outline-strong is at least 3.49:1), section shape is canonical, and the flat, no-guilt posture is applied consistently. The weak spots are outside that loop. Several P1 surfaces have an IA row but no visual or behavioural spec: the progress view, the Goal entry form, Strategy and Restriction entry, the Plan editor and Appointment Feedback. FR-10's pause, adapt, skip and second-Activity controls are missing from Practice. The PRD's caregiver-membership notifications conflict with the spine's "never notify about the other Caregiver" rule. And there is no rule for a Domain outside the six tinted ones. No critical findings. Story-dev can start on the core loop now, but the five high findings should be closed before those epics are written.

## 1. Flow coverage — adequate
Checked: all five UJs (UJ-0 to UJ-4) and FR-1 to FR-18 against Key Flows, IA and Component Patterns. Every UJ has a flow with a clear protagonist role (illustrative composites, per the memlog privacy override), numbered steps and a bolded climax. Flows 0 and 1 have failure paths. Flows 2, 3 and 4 do not.
### Findings
- **high** FR-10's testable consequences are missing from Practice. The PRD requires pause, adapt (switch to a variation), skip an Activity, and stop, and says a Practice Session holds one or two Activities. The Practice screen offers only Marks, the timer, the Prep card link and Done, and there is no way to move to a second Activity (EXPERIENCE.md › Component Patterns › Practice screen; Key Flows › Flow 1). *Fix:* add Pause, "Try a variation" and "Skip / next Activity" controls to the Practice screen row (quiet, non-gesture), define how a two-Activity Practice Session sequences into one Review, and add a matching DESIGN.md Components entry.
- **high** Several P1 entry surfaces have an IA row but no component pattern, so story-dev would have to invent the forms. These are the manual Goal form (FR-4: fields, the "describe it as an observable behaviour" prompt, and the original wording kept beside a Caregiver edit), manual Strategy, Restriction and prescribed-Activity entry (FR-7), editing an Observation later with edit history (FR-14), and viewing or deleting an uploaded original (FR-5) (EXPERIENCE.md › IA rows Add or import, Goal detail; Component Patterns). *Fix:* add Component Pattern rows for a Goal form, a Strategy/Restriction form, Observation edit (with a history affordance) and Original file (view/delete, retention note), each with a matching DESIGN.md Components line.
- **medium** Flow 2 (UJ-2) has no failure or edge path, although the UJ names one: an OT report with no measurable criteria becomes a Narrative Goal. An unreadable photo or unavailable AI is also uncovered (EXPERIENCE.md › Key Flows › Flow 2). *Fix:* add "Failure: OT report with broad goals → saved as Narrative Goals; unreadable photo or AI unavailable → manual-entry route stays open."
- **medium** Flows 3 and 4 have no failure paths (EXPERIENCE.md › Key Flows › Flow 3, Flow 4). *Fix:* Flow 3: invite expired, or consent not given → the account can't be used, with plain copy. Flow 4: a Goal under 5 Observations shows "limited data", and with no share sheet the fallback is PDF download.
- **low** The Flow 1 climax ("Review saved") replaces UJ-1's in-Activity climax (the child settles and the parent had a workable next step), and Guided mode (UJ-1's Alternative) appears in no flow (EXPERIENCE.md › Key Flows › Flow 1). *Fix:* make step 4 the climax, or note that the UJ climax maps to step 4. Add a one-line Guided-mode alternative.

## 2. Token completeness — adequate
Checked: every key under `colors`, `typography`, `rounded`, `spacing` and `components`, plus every `{path}` reference in the prose and component objects of both files. All 29 light colors have a hex value and a `-dark` twin. I recomputed the contrast claims and they hold: ink-soft on lilac 5.29, parent-proposed on honey-soft 5.29, outline-strong on card 3.73 and on floor 3.49, dark outline-strong on dark card 3.67. `{colors.focus-ring}` and `{spacing.content-max}` in EXPERIENCE.md resolve.
### Findings
- **medium** Overlays use a scrim but no scrim token exists. Elevation & Depth makes "a dim scrim, not a shadow" the only separation for sheets and dialogs (DESIGN.md › Elevation & Depth; frontmatter `colors`). *Fix:* add `scrim` and `scrim-dark` (hex plus opacity) and reference them from `coach-tip-sheet`.
- **medium** `{colors.domain-*}` is a wildcard that no resolver can flatten. It appears in `hero-band.background` and `cue-tile.background` (DESIGN.md frontmatter `components`). *Fix:* state the binding rule explicitly (e.g. `background: '{colors.domain-<activity.domain>}'` plus a note) and pair it with the Domain fallback in §7.
- **medium** Visual states named in EXPERIENCE.md have no tokens. These are the uncertain-field highlight ("Please check this."), the masking cover block, the danger button fill or foreground (it is unclear whether `danger` is text or fill), and the offline line or deletion banner (EXPERIENCE.md › State Patterns, Component Patterns › Masking review, Destructive confirm). *Fix:* add `attention`/`attention-soft` (non-traffic-light) and `mask-cover` tokens with dark twins, plus `danger-foreground`, and state how `danger` is applied.
- **medium** The Selected wash is overloaded. `mark-button.background` is `{colors.selected}`, the same token that means "selected" on choice chips. At rest, Mark buttons look selected, and their boundary is 1.10:1 against floor (1.42:1 dark) with no outline (DESIGN.md › Components › Practice screen; frontmatter `mark-button`). *Fix:* give Mark buttons their own token (e.g. `mark` / `mark-dark`) distinct from `selected`, and record the WCAG 1.4.11 rationale: the text label identifies the control, and flat with no outline is the PO's choice.
- **low** Several values sit off the scale as literals: `block-card.padding: 14px`, `hero-band.padding: 16px 20px 22px`, `plan-row.radius: 18px` (not in `rounded`), `cue-number.size: 44px`, `ai-label.border: 1px` (should be `{spacing.outline-width}`), and the "24–28px" group gap and "560px" sheet width. `rounded.sm` is never used (DESIGN.md frontmatter; Layout & Spacing; EXPERIENCE.md › Responsive & Platform). *Fix:* snap these to scale tokens or add named tokens, and drop or assign `rounded.sm`.

## 3. Component coverage — thin
Checked: 20 DESIGN.md frontmatter components and the prose Components, against 20 EXPERIENCE.md Component Pattern rows. The core-loop components (Today card, Prep card, Mark button, Coach Tip sheet, Review form, Choice chips, Stepper, Status line, Source badge, AI label) have both visual and behavioural specs. Coverage beyond the loop is thin.
### Findings
- **high** The progress view (FR-16, P1) has no spec in either spine. It holds the three separate measures, the Observation count, attention duration "never as a target", AI descriptions that cite Observations, and lineage back through revised Goals. It is the UJ-3 climax and feeds the Summary (EXPERIENCE.md › IA › Goal detail; DESIGN.md › Components). *Fix:* add a Progress view row to both spines covering the chart or list form per Criterion type, how the three measures are separated, the attribution of who logged each Observation, the AI-label placement, and the visual rule against traffic lights or percentages.
- **medium** Several EXPERIENCE.md components have no DESIGN.md visual spec: the Log a moment sheet (only the button is specified), Masking review, Draft review, Confirm-to-share, Destructive confirm, Nudge and Timer (DESIGN.md › Components). *Fix:* add one visual line each (surface, radius, tokens, state appearance).
- **medium** Several surfaces have no component in either spine: the Plan editor (FR-13: accept or edit, item count, days and Contexts, weekly availability, week start), the Appointment Feedback form (FR-18), the Summary preview or builder, the consent cards, Goal rows and grouping in Goals, Activity library rows (favourite and hide) and the Inventory entry (FR-15, P2) (EXPERIENCE.md › IA). *Fix:* add behavioural rows, and visual lines where the spine is the only spec.
- **medium** Component names drift between the files: "Plan strip" (EXPERIENCE.md) vs "Plan rows" and "This week" (DESIGN.md) vs `plan-row`; "Helpful toggle" vs "Helpful toggle chip"; "Badges and labels" / "Source badges" vs "Source badge" (DESIGN.md › Components; EXPERIENCE.md › Component Patterns). *Fix:* pick one name per component and use it in both files and the frontmatter.
- **low** The Stepper row says it "shows 'X of Y' as two steppers", but attention minutes uses a single stepper (EXPERIENCE.md › Component Patterns › Stepper vs Review form). The Choice chips row omits who-modelled and the multi-select "Which cue or tip helped?" variant. *Fix:* cover both the single and paired stepper modes, and list the multi-select chip variant.

## 4. State coverage — thin
Checked: each of the 19 IA surfaces against empty, cold-load, focus, error, offline and permission-denied states. Offline, AI-slow, Restriction-blocked, limited data, narrative, retired, not attempted, deletion pending and removed Caregiver are all well covered. Focus is covered globally (Accessibility Floor).
### Findings
- **high** The PRD's caregiver-membership notifications are unspecified and appear contradicted. FR-1 says "the remaining Caregivers are notified" when a Caregiver is removed, and §5 says Family deletion "notifies the other Caregivers". The spine's Notifications section says "Never: notifications about the other Caregiver's activity" with no carve-out, and no surface shows how these notices arrive (EXPERIENCE.md › Notifications; State Patterns). *Fix:* carve out membership and deletion events (they are security notices, not activity), and specify the channel (in-app banner on Today, plus email via the invite mail path) and the copy.
- **medium** No loading or cold-load pattern exists anywhere: Today on a cold open, Summary draft generation, import OCR and extraction progress, Prep card fetch (EXPERIENCE.md › State Patterns). *Fix:* add a loading row (a skeleton or `meta` line, no spinners that read as waiting on AI for curated content).
- **medium** Permission and consent states are missing: camera permission denied for Photo import, push permission declined, consent not given (FR-1: "the account cannot be used"), and an invite link that is invalid or expired (EXPERIENCE.md › State Patterns; Privacy & Consent Surfaces). *Fix:* add a row for each with copy and the route forward.
- **medium** There is no non-offline error state. A Save rejected by the server, an expired OIDC session mid-Review, or a failed upload has no treatment. "No error dialogs" is stated only for sync (EXPERIENCE.md › State Patterns). *Fix:* add a generic recoverable-error row (the draft is kept, re-auth returns to the same Review) in the Voice and Tone style.
- **medium** Empty states are missing for Goals (none yet), Activities (no favourites, everything hidden, or every AI suggestion silently blocked by Restrictions, which leaves an empty list with no message), Share (no Summaries yet), and a Summary for a Goal Period with zero Observations (EXPERIENCE.md › State Patterns). *Fix:* add empty-state rows. For all-blocked suggestions, show a neutral "No new ideas right now" without revealing the Restriction.
- **low** An abandoned open Practice Session has no resolution. The Practice Session "never times out" and reopening returns to Practice, but nothing says what happens the next day. WebKit storage eviction for offline drafts (addendum §B) is also not reflected (EXPERIENCE.md › Component Patterns › Practice screen; Accessibility Floor › Time limits). *Fix:* define when a stale open Practice Session prompts for Review or a neutral close, and note prompt sync for queued Observations.

## 7. Inheritance discipline — adequate
Checked: `sources` paths resolve (`../../prds/prd-little-steps-2026-11-05/prd.md` and `addendum.md`). UJ and FR IDs are cited throughout. Glossary terms (Prompt Level list, Context values, Review Status, Status Vocabulary, Mark names, "Not attempted / child not available") are verbatim. EXPERIENCE.md token references resolve to DESIGN.md.
### Findings
- **high** The spine fixes a six-Domain tint set, but the PRD's Domain is open-ended. PRD §3 lists joint attention, play, imitation, understanding language and fine motor as examples, §2 names sensory, and L-3 adds oral-motor. Imports extract a free-text domain (UJ-2 step 3). Nothing says how "understanding language" or "fine motor" maps to a tint, or what an unmapped Domain gets (DESIGN.md › Colors › Domain tints; EXPERIENCE.md › Component Patterns › Domain tint). *Fix:* state whether Domain is a fixed enum (and list how PRD example Domains map to it), or define a mapping rule plus a neutral fallback tint (e.g. a `domain-other` token with a dark twin). Feed the answer back to the PRD glossary if it becomes an enum.
- **medium** FR-17's date-range option is dropped. FR-17 allows a Summary for "either a date range or a Goal Period", but the Summary builder offers only the Goal Period (EXPERIENCE.md › IA › Summary builder; Flow 4 step 1). *Fix:* add a date-range option to the builder.
- **medium** The spine's own two-tap rule is contradicted by its IA. "Every surface can be reached in two taps or fewer from Today, except Settings sub-pages", yet Appointment Feedback (Share → Summary → After the appointment) and New Goal Period (Goals → Care Team Member → New period) take three (EXPERIENCE.md › IA › Rules). *Fix:* widen the exception, or add shortcuts (e.g. an "After the appointment" entry on the Summaries list).
- **low** The files use "Goal Domain", but the glossary term is "Domain". Flow titles paraphrase the UJ names rather than quoting them (the IDs are present, so they stay traceable) (DESIGN.md › Colors; EXPERIENCE.md › Key Flows). *Fix:* use "Domain", and optionally quote the UJ title after the ID.
- **low** The Status line says "no toast animation" in DESIGN.md but "fades after about 4 seconds" in EXPERIENCE.md, and the fade has no Reduce Motion rule (DESIGN.md › Components › Status line; EXPERIENCE.md › Component Patterns › Status line). *Fix:* either drop the fade or define it as an opacity change that Reduce Motion skips.
