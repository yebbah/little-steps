- (direction) Fast path chosen. Deliverables: spine (build substrate) + HTML walkthrough for human readers.
- (constraint) Stack ADOPTED from PRD addendum §A: Java/Spring Boot REST, Spring Security resource server, Spring Data JPA + Flyway on PostgreSQL, Keycloak OIDC (PKCE), Spring AI behind one AI port (Ollama local, hosted at ship), React+Vite PWA, Docker Compose + Mailpit, Tailscale for device HTTPS, Spring scheduler for jobs, storage interface local-fs/S3.
- (constraint) Hard NFRs: runs end-to-end on a Mac at no cost; portable to cheap hosting without code change; <=US$5/family/month; tips <2s; offline-tolerant practice; logs never carry child content; WCAG 2.1 AA; English only but strings externalised.
- (constraint) Privacy: family-only access, no operator access except caregiver-granted time-limited support; audit log append-only, family-readable; masking before any AI call on imports; 7-day undoable family deletion; 12-month retention of originals; full data export.
- (decision) Paradigm: modular monolith (Spring Modulith) with hexagonal ports for every external system (AI, OCR, masking, storage, email, push, PDF). Prevents: modules reaching into each other's tables; vendor SDKs leaking into domain code.
- (decision) Module boundaries fixed: family, child, careteam, goals, library, practice, planning, progress, summary, import, ai, notifications, audit, privacy, shared kernel. Cross-module only via module API package or domain events; no cross-module JPA associations (id references only); verified by ApplicationModules.verify() test.
- (decision) Tenancy: every family-owned table has family_id NOT NULL FK families ON DELETE CASCADE; Hibernate @TenantId discriminator with resolver from authenticated caregiver's membership. Prevents a query path that forgets family scoping.
- (decision) Identity: Keycloak owns credentials only; app Caregiver keyed by OIDC sub; app owns Family, membership, invites (app-issued single-use tokens), consent records. Consent gate: all family-data endpoints refuse with problem type consent-required until consent recorded.
- (assumption) [ASSUMPTION] A Caregiver belongs to at most one Family in v1 (one Child Profile per Family is confirmed; multi-family caregivers not in scope).
- (decision) IDs: UUIDv7 for every entity, generated by the client for anything creatable offline; creates are idempotent PUT /{collection}/{id}. Prevents duplicate rows on outbox replay.
- (decision) Offline sync: PWA outbox in IndexedDB (Dexie). Every mutation is a queued command replayed FIFO; server write endpoints idempotent. Shared editable records carry version; stale write -> 409, client keeps local draft and shows it for re-apply (never silently dropped, never last-write-wins).
- (decision) Practice Session is client-authoritative until closed: Marks, timer, helpful-tip toggles held locally, submitted with the Review as one idempotent command. Server never holds a half-open session.
- (decision) Observations append-only: edits create a new revision row with author+time; current = latest. Audit log separate append-only table, IDs/enums only.
- (decision) Provenance: every Goal, Strategy, Restriction, Activity, Coach Tip carries source (careteam member id | caregiver id) and origin (prescribed | curated | ai_suggested | parent_proposed). Care Team original wording immutable; caregiver edits stored in separate field.
- (decision) Single Restriction store owned by goals module; Child Profile 'avoid' sensitivities materialise as Restrictions (via event). Guardrail reads only this store.
- (decision) AI: only the ai module calls Spring AI. Each use case is a named AiTask with typed input built from an allow-list (nickname or 'the child', goal/observation content); structured output validated against schema; every output passes guardrail pipeline (deterministic Restriction check then scope classifier) before return; fail-closed (unchecked = dropped). Curated tips go through the same Restriction check.
- (decision) Traceable AI text: summary/progress AI sentences must cite Observation ids in scope; server rejects uncited sentences. Goal status fields writable only through Appointment Feedback from caregiver input; AI output schema has no status field.
- (decision) Import pipeline states uploaded->text_read->masking_confirmed->extracted->reviewed; extraction refuses documents lacking caregiver masking confirmation; ai receives only masked lines/image; originals stored encrypted via StoragePort, never passed to ai.
- (decision) Time: instants stored UTC timestamptz; Family holds IANA timezone + week start; day/week boundaries computed server-side in family tz; Plan keyed by (family, local week start). Unfinished items have no carry path by construction.
- (decision) Scheduled jobs (reminders, retention purge, deletion purge, pilot-end) are idempotent and driven by due-state columns, so double-run is harmless; single app instance assumed.
- (decision) Family deletion: soft request with purge_after=+7d; purge = delete families row (cascade) + storage prefix families/{id}/; only a contentless tombstone remains. Export via ExportContributor per module; purge via cascade + StoragePort.
- (decision) API: REST JSON under /api/v1, RFC 9457 problem details, springdoc OpenAPI generated from code; frontend types generated with openapi-typescript (no hand-written DTO types).
- (decision) User-facing strings in frontend message catalogs; server returns codes/enums, never UI sentences (except content: curated library, AI text, notification templates in notifications module catalog). Curated content (library, cues, tips) as reviewed YAML in repo, loaded idempotently at startup by stable slug + content version.
- (decision) Logging: ids and enums only; child/goal/observation text wrapped in value types with redacted toString; prompts and AI outputs never logged; AI eval metrics as counters.
- (decision) Frontend: server state via TanStack Query; offline data + outbox in Dexie; no global store mirroring server data; Radix primitives styled with DESIGN.md tokens as CSS custom properties.
- (assumption) [ASSUMPTION] Styling via plain CSS modules + token CSS variables (no Tailwind).
- (decision) Delivery: one app container (Spring Boot serves the built PWA, same origin as API); Keycloak + Postgres + Mailpit(local) in Compose; same compose file with env overrides on a VM. Config only by env/profiles (local, test, prod). Ollama native on host.
- (decision) Testing: Testcontainers Postgres for persistence tests (no H2); Modulith verify test; guardrail eval set (>=30 cases) in repo under eval/guardrails, release gate requires passing report for the model configured in that environment.
- (assumption) [ASSUMPTION] Maven build; repo layout backend/ + frontend/ + content/ + eval/ + deploy/; npm.
- (decision) Encryption at rest: volume/disk encryption for Postgres; uploaded originals additionally app-encrypted (AES-GCM, key from env) before StoragePort write.
- (question) Support access grant (caregiver grants time-limited operator access): mechanism undecided; revisit before pilot launch.
- (question) Which local/hosted model: decided by guardrail eval pass + cost ceiling; revisit at P2 start.
- (question) OCR adapter (Tesseract container vs vision model) for OcrPort: decide at P2 import epic; contract is lines + bounding boxes in reading order.
