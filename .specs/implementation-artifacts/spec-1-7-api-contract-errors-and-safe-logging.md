## Intent

**Problem:** The backend has no error format, no API contract and no protection against child content reaching the logs, so the first endpoint would set the pattern by accident.

**Approach:** One RFC 9457 error format from a problem-type registry, a springdoc-generated `openapi.json` that drives generated TypeScript types with a drift check, redacting value types for Caregiver and AI text, structured JSON logs with a request ID, and an empty frontend message catalog with a lint rule against literals in JSX. Source: GitHub issue #32, AD-19 and AD-20.

## Boundaries & Constraints

**Always:**
- Failed requests return `application/problem+json` with `type` from `shared/web/ProblemTypes`, also when the client sends `Accept: text/html`. Responses never echo exception messages or request values (no `detail`); they carry `requestId`.
- `CaregiverText` and `AiText` return `[redacted]` from `toString()`; the raw value is only available through `reveal()`.
- Logs are JSON on stdout (Spring structured logging, ECS), with `requestId` from the logging context. One access line per request (method, path, status, duration); no query string, headers or bodies. Unhandled exceptions log the class name and the full stack trace (human decision on #32; replaced by error references in #91).
- `openapi.json` is generated by a build test and compared with the committed `backend/openapi.json`; `npm run api:types` generates `frontend/src/api/schema.d.ts` with `npx -p typescript@5.9.3 -p openapi-typescript@7.13.0`; `npm run api:check` fails when it is out of date.
- Frontend: empty message catalog (`src/i18n/messages.ts`), `react/jsx-no-literals` as error in oxlint (the repo's linter).

**Never:**
- No database, auth, Spring Modulith or module skeleton (Story 1.6). No Swagger UI; springdoc API docs stay off unless a test or profile turns them on. No change to the security gate.

## Implementation Notes

- Decisions (no human gap): problem type URIs are URNs (`urn:littlesteps:problem:<slug>`) so they name no host; `ProblemTypes` is an enum. The spec says ESLint; the repo lints with oxlint, which has the same `react/jsx-no-literals` rule, so no second linter was added (`ignoreProps: true`, so attributes such as `className` are not flagged).
- Story 1.6 (#31, module skeleton) merged first; this branch was rebased onto it. `pom.xml`, `application.properties`, README, architecture and index conflicts were resolved by keeping both sides, and the web tests now extend `IntegrationTest` (real PostgreSQL via Testcontainers). `ModularityTests` passes with the `shared.web` and `shared.text` packages.
