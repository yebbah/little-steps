## Summary

Epic 1 delivers the local environment and engineering foundation for LittleSteps. A developer can start PostgreSQL, Keycloak and Mailpit with one script from hardened images pinned by digest, run the app as it ships, and rely on a security scan before every commit and in CI. The backend now has its module skeleton with enforced boundaries, real-database tests, one error format, a generated API contract and logs that cannot leak caregiver text, so every later feature lands in the right place and fails the build if it crosses a boundary.

## New features

One entry per story, with its changelog and security report.

- **Story 1.1, Scaffold the repository.** The repository had only a README and the planning documents. This story adds the backend and frontend projects, pinned to the versions in the architecture, so every later story has a project and layout to build on. ([changelog](../changelogs/story-1-1-scaffold-the-repository.md))
- **Story 1.2, Security scan before every commit.** Every commit is now scanned for leaked secrets and for vulnerable backend, frontend and image components. A finding in the CISA KEV catalog, or with a CVSS of 7.0 or more, blocks the commit. ([changelog](../changelogs/story-1-2-security-scan-before-every-commit.md), [security report](../security-reports/story-1-2-security-scan-before-every-commit.md))
- **Story 1.3, Hardened local infrastructure with Docker Compose.** One compose file now runs the local PostgreSQL, Keycloak and Mailpit services from images pinned by digest, with a Keycloak realm that is imported on start. A check script fails when the compose file and the image manifest disagree, and the image scan from Story 1.2 now scans real images. ([changelog](../changelogs/story-1-3-hardened-local-infrastructure.md), [security report](../security-reports/story-1-3-hardened-local-infrastructure.md))
- **Story 1.4, Start and stop scripts.** `deploy/dev-up.sh` now checks every prerequisite, enables the git hook, prepares `local.env`, starts the compose stack and waits for it to be healthy. `deploy/dev-down.sh` stops it, and `--wipe` resets it after typed confirmation. First-time setup in the README uses only these scripts. ([changelog](../changelogs/story-1-4-start-and-stop-scripts.md), [security report](../security-reports/story-1-4-start-and-stop-scripts.md))
- **Story 1.5, Hardened app image and full mode.** The app can now be run as it will ship. One multi-stage `deploy/Dockerfile` builds the PWA and the Spring Boot jar (PWA inside) on pinned Docker Hardened Images and runs it as a non-root user. `deploy/dev-up.sh --full` builds and starts it, and the Vite dev server proxies `/api` and `/actuator` for day-to-day development. ([changelog](../changelogs/story-1-5-hardened-app-image-and-full-mode.md), [security report](../security-reports/story-1-5-hardened-app-image-and-full-mode.md))
- **Story 1.6, Backend module skeleton and persistence baseline.** Every feature now has a module to land in, and the build fails when a module crosses a boundary. The backend has one package per AD-1 module, Spring Modulith verification, a Flyway migration layout, the JPA event publication registry, environment-only configuration with `local`, `test` and `prod` profiles, and an `IntegrationTest` base that runs against a real PostgreSQL in Testcontainers. ([changelog](../changelogs/story-1-6-backend-module-skeleton-and-persistence-baseline.md), [security report](../security-reports/story-1-6-backend-module-skeleton-and-persistence-baseline.md))
- **Story 1.7, API contract, errors and safe logging.** The backend now answers every failed request in one format (RFC 9457 problem+json from a type registry), publishes its API as a generated `openapi.json` that drives generated TypeScript types, and keeps Caregiver and AI free text out of the logs. The frontend gets an empty message catalog and a lint rule against string literals in JSX. ([changelog](../changelogs/story-1-7-api-contract-errors-and-safe-logging.md), [security report](../security-reports/story-1-7-api-contract-errors-and-safe-logging.md))
- **Story 1.8, Continuous integration with security and quality gates.** Every push and pull request is now checked by `.github/workflows/ci.yml` on free GitHub-hosted runners: backend build and tests with coverage, frontend lint, typecheck, tests and build, script and manifest checks, and the security scan over the commit history and the backend and frontend dependencies. Image scans stay manual (#95). A skipped local hook no longer lets an unsafe or broken change through. ([changelog](../changelogs/story-1-8-ci-security-quality-gates.md), [security report](../security-reports/story-1-8-ci-security-quality-gates.md))
- **Story 1.9, Release notes for each epic.** Closing an epic now produces a release note from the repository's real facts instead of memory. `deploy/release-notes.sh <epic>` fills the template, and a check refuses a note that still has TODOs or reports KEV or High/Critical findings. ([changelog](../changelogs/story-1-9-release-notes-for-each-epic.md), [security report](../security-reports/story-1-9-release-notes-for-each-epic.md))

### API changes, breaking changes and upgrade steps

API changes: the first endpoint, `GET /api/v1/ping`. Every failed request returns RFC 9457 `application/problem+json` with a `type` from `ProblemTypes` (`urn:littlesteps:problem:<slug>`), no `detail`, and a `requestId` that is also sent as the `X-Request-Id` header. `backend/openapi.json` is the committed contract and the build fails when it drifts. There are no breaking changes (new project).

Upgrade steps, in order:

1. `docker login dhi.io` (Docker Hardened Images account).
2. `deploy/dev-up.sh` (add `--full` to also build and run the app image).
3. For IDE runs, export the `deploy/local.env` variables and set `SPRING_PROFILES_ACTIVE=local`.
4. `(cd frontend && npm ci)`, then `npm run api:types` after any endpoint change.
5. Add the repository secrets `DHI_USERNAME` and `DHI_TOKEN` so CI can pull the PostgreSQL image for the backend tests.
