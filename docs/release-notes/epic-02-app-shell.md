## Summary

The frontend is no longer a bare page. It now has the Playroom design system (tokens, light and dark, type, Domain tints, object icons), the shared controls and surfaces, a message catalog with a tone check, an app shell with five destinations, Settings with a theme choice, and an installable, offline-capable shell. Every screen is checked for accessibility and reflow on each pull request, so the feature epics that follow build on a floor that is already tested.

## New features

One entry per story, with its changelog and security report.

- **Story 2.1, Design tokens, theme and type.** The frontend gets its Playroom visual foundation: every DESIGN.md colour, type, spacing and radius token as CSS custom properties, light and dark modes that follow the device or a stored choice applied before first paint, and a dev-only component gallery at `/dev/gallery`. Stylelint keeps the design flat and the focus outline in place. ([changelog](../changelogs/story-2-1-design-tokens-theme-and-type.md), [security report](../security-reports/story-2-1-design-tokens-theme-and-type.md))
- **Story 2.2, Domain tints and icons.** Free-text Domains now map to one of the seven DESIGN.md tint families, and the frontend gets the object line icons and icon tiles the shell and screens will use. Both are shown in the gallery. ([changelog](../changelogs/story-2-2-domain-tints-and-icons.md), [security report](../security-reports/story-2-2-domain-tints-and-icons.md))
- **Story 2.3, App shell, navigation and focus management.** The app gets a shell: five places reachable from a bottom nav or a left rail, a skip link, landmarks, one status region and a rule that every route change sets the title and focuses the page heading. Later screens plug into it instead of inventing their own navigation and focus handling. ([changelog](../changelogs/story-2-3-app-shell-navigation-and-focus-management.md), [security report](../security-reports/story-2-3-app-shell-navigation-and-focus-management.md))
- **Story 2.4, Core controls.** The frontend gets its shared form controls, so later screens do not each re-invent buttons, fields, chips and steppers, and the accessibility floor (focus ring, 48px targets, `aria-disabled`, no colour-only state) stays in one place. The gallery shows them in every state at 360, 768 and 1280px. ([changelog](../changelogs/story-2-4-core-controls.md), [security report](../security-reports/story-2-4-core-controls.md))
- **Story 2.5, Surfaces, feedback and labels.** The frontend gets its shared surfaces, feedback and label components, so later screens use one card, sheet, status line, banner and source label instead of inventing their own. Sheets and dialogs follow the modal focus rules (R-04) and the status line follows the clearing rules, in one place. ([changelog](../changelogs/story-2-5-surfaces-feedback-and-labels.md), [security report](../security-reports/story-2-5-surfaces-feedback-and-labels.md))
- **Story 2.6, Message catalog and tone check.** The frontend message catalog now holds its first strings, the two standard labels, and a tone check fails the build when a catalog string contains judging or alarming wording. A checklist of banned UI patterns gives reviewers one place to check against. ([changelog](../changelogs/story-2-6-message-catalog-and-tone-check.md), [security report](../security-reports/story-2-6-message-catalog-and-tone-check.md))
- **Story 2.10, Catalog copy for status lines, banners and empty states.** The message catalog now holds every status line, banner, empty-state and in-progress string the UX spine names, under stable keys, with a test that fails when a spine string is missing or reworded. A small `tf()` helper fills value placeholders. Errors, destructive confirmations, security notices, consent, camera, invite and session strings follow in Story 2.11. ([changelog](../changelogs/story-2-10-catalog-copy-for-status-lines-banners-and-empty-states.md), [security report](../security-reports/story-2-10-catalog-copy-for-status-lines-banners-and-empty-states.md))
- **Story 2.11, Catalog copy for errors, confirmations and security notices.** The message catalog now holds every error, destructive or share confirmation, consent and permission notice, invite string and security notice that the UX spine names exactly, under stable keys, with a test that fails when one is missing or reworded. Together with Story 2.10 the catalog covers the strings the spine names for the core states. ([changelog](../changelogs/story-2-11-catalog-copy-for-errors-confirmations-and-security-notices.md), [security report](../security-reports/story-2-11-catalog-copy-for-errors-confirmations-and-security-notices.md))
- **Story 2.7, Responsive reflow and accessibility test harness.** Every screen now reflows for large text, a short viewport and a screen reader, and a CI job proves it on every pull request: axe on every shell screen and the gallery frames in light and dark, no horizontal scroll or clipped label at 320px and 200% text, the reflow rules and no state shown by colour alone. ([changelog](../changelogs/story-2-7-responsive-reflow-and-accessibility-test-harness.md), [security report](../security-reports/story-2-7-responsive-reflow-and-accessibility-test-harness.md))
- **Story 2.8, PWA shell and install offer.** LittleSteps can now be added to a home screen and opens like an app, while every feature still works in the browser. The service worker keeps the app shell only, never an API response, and later epics get two hooks: `offerInstall()` to ask at a good moment, and `useAppUpdate()` to apply a new version safely. ([changelog](../changelogs/story-2-8-pwa-shell-and-install-offer.md), [security report](../security-reports/story-2-8-pwa-shell-and-install-offer.md))
- **Story 2.9, Settings shell and theme choice.** The Caregiver can open Settings from Family, choose Light, Dark or System, and bring the home-screen install offer back after "Not now". The theme applies at once, is stored on the device and is applied before first paint. ([changelog](../changelogs/story-2-9-settings-shell-and-theme-choice.md), [security report](../security-reports/story-2-9-settings-shell-and-theme-choice.md))
